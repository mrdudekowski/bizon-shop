# CMS и сайт: синхронизация контента и интерфейсов — план исправлений

> **Для реализации:** выполнять по фазам, сохранять существующие изменения в обоих репозиториях и проверять CMS, backend и сайт раздельно. До отдельного сигнала пользователя код не менять и ничего не публиковать.

**Цель:** сделать так, чтобы поля, классификация и статус «На сайте» в CMS предсказуемо отражались в публичном каталоге шин, дисков и Shop, а пользователи сайта могли находить и понимать опубликованный контент.

**Архитектура:** CMS остаётся рабочим интерфейсом контента; backend — контрактом опубликованных данных; публичный сайт отображает этот контракт. Для каждого типа сущности составляется полевая матрица CMS → БД/API → UI. Данные маркетинговых страниц можно сохранить, но привязать к категориям каталога, чтобы редакционный контент и товарная таксономия не создавали конкурирующие категории.

**Стек:** существующие Next.js/React/TypeScript приложения CMS и сайта, backend Node HTTP, текущая схема Postgres, публичные `Cms*` контракты, CSS Modules и действующие UI-компоненты.

## Критерии завершения

- Каждый документ со статусом «На сайте» доступен по публичному маршруту либо CMS блокирует публикацию с понятной причиной.
- CMS и API согласованно передают тип, статус, slug, классификацию, изображения, варианты и родителя.
- Фильтр Regional действительно находит региональные шины; направление OTR открывает понятный пустой экран вместо 404.
- Shop-индекс состоит из CMS-публикованных категорий; маркетинговая подача не создаёт дублирующих/перехватывающих каталогов.
- Подкатегория работает в CMS, в каждой публичной категории и в URL; ни отдельные плитки, ни новые товарные спецификации автоматически не создаются.
- Ошибку backend невозможно принять за пустой каталог.
- Диски сохраняют единую коллекцию кованых моделей без фиктивных категорий; публичные поля модели и вариантов совпадают с тем, что можно редактировать в CMS.
- Сквозная сверка показывает отсутствие неожиданных различий между опубликованными CMS-записями, API и фактическими страницами сайта.
