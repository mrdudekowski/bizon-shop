# CMS и сайт: результаты реализации

Дата: 2026-09-27

## Реализовано

| Контент | Цепочка CMS → backend/API → сайт | Результат |
|---|---|---|
| Публикация товара Shop | Категория со статусом `published` проверяется перед публикацией товара; CMS блокирует действие заранее и показывает ссылку на категорию | Нельзя получить статус публикации у товара в черновой категории. Категорию с опубликованными товарами нельзя скрыть, пока товары не сняты с публикации. |
| Применение шин | `applicationTypes` читается из связанной таблицы, попадает в API и фильтруется как массив | Известные legacy-значения `long-haul` и `off-road` распознаются вместе с каноническими ключами. Фильтр Regional находит DSR188. |
| Направления шин | Чтение каталога сохраняет опубликованные типы без моделей | OTR открывается с объяснением, что направление опубликовано, а модели ещё готовятся. |
| Shop-категории | Индекс и страницы берут опубликованные категории из API; сортируют по данным CMS и используют CMS-фото, если оно задано | CMS-категория при совпадении slug имеет приоритет над старым статическим маршрутом Accessories/Outdoor. Редакционные обложки для этих двух slug остаются резервным оформлением. |
| Подкатегории Shop | Фильтр строится по опубликованным товарам, хранится в `?subcategory=...`, переживает прямое открытие и Back/Forward | Подкатегории остаются значениями фильтра, не отдельными карточками. На карточке товара показаны имя категории и назначенная подкатегория. |
| Ошибки чтения | Клиент API сохраняет 404 как отсутствие записи, но поднимает сетевые и серверные ошибки | Страница показывает состояние ошибки с повторной загрузкой, вместо ложного пустого каталога. |
| Проверка синхронизации | Добавлен read-only `check-catalog-sync.mjs` | Сверяет опубликованные CMS-записи с публичным API и проверяет HTTP-маршруты, родительскую публикацию и неизвестные применения шин. |
| Сводка размеров шин | Карточка каталога считает уникальные размеры; повторяющиеся варианты остаются доступны на странице модели | В браузере DSR188 показывает один `12.00R20`, а не повторённую подпись. |
| Коллекция дисков | Заголовок, SEO title и описание страницы `/shop/wheels/forged` берутся из опубликованного типа дисков CMS | Текст коллекции больше не задаётся отдельной статической копией; модели остаются карточками коллекции `forged`. |

## Не менялось

- Статусы и содержимое реальных CMS-записей вручную не редактировались.
- Не добавлялись товарные характеристики, бренд, варианты или изображения, которых нет в текущей спецификации CMS. Для этих полей перед расширением схемы нужна согласованная модель товара.
- Не создавались схемы предпросмотра черновиков: в текущем приложении не найден существующий защищённый preview-токен.
- Диски используют существующую внутреннюю связь с типом `forged`; публичная коллекция и специальные страницы кованых дисков уже работают через этот маршрут. Новые категории и фиктивные спецификации не добавлялись.

## Проверки

- CMS: `npm run typecheck` — успешно; целевые `localStore` и domain-тесты — 29 пройдены.
- Backend: целевые mapper, published-reader и publication-rule тесты — 18 пройдены.
- Публичный сайт: целевые фильтры шин, read model, Shop URL-filter и API client — 15 тестов пройдены.
- Представление коллекции дисков: `node --test src/components/shop/forgedView.test.mjs` — 4 теста пройдены.
- Публичный `npm run lint` и CMS `npm run lint` — без ошибок; остались существующие предупреждения об `<img>`/зависимостях хуков.
- Публичный `npm run typecheck` завершился ошибками в backend/admin типизации (`postgresAdmin.ts`), тестовых фикстурах (`mapPage.test.ts`, `mapTire.test.ts`), типе `ProcessEnv`/target (`objectStorage.ts` и его тест) и narrowing в `src/app/api/requests/route.ts`. Ошибок в затронутых страницах Shop и каталога не появилось.
- Локальная сверка `node check-catalog-sync.mjs` на работающих портах 4000/3010: **in sync**; найдено 2 направления и 3 модели шин, 1 тип и 5 моделей дисков, 4 Shop-категории и 1 товар; missing/extra/blocked parent/unmapped application/broken routes — пусто.
- Runtime и браузер (публичный сайт, порт 3010): `/models/tbr?application=regional` показывает DSR188, выбранный фильтр Regional и один уникальный `12.00R20`; `/models/otr` показывает доступное направление с объяснением пустого каталога; `/shop/categories` показывает четыре CMS-категории; `/shop/pritsepy` показывает CMS-товар «Мега прицеп»; `/shop/wheels/forged` показывает имя и описание из CMS, а также пять дизайнов дисков.

## Оставшиеся решения

1. Утвердить общую спецификацию Shop-товара (бренд, тип, параметры вариантов и связь изображений) до расширения CMS/API-схемы.
2. Для live Postgres отдельно проверить фактический запрет `publishShopProduct` и снятия категории с публикации на изолированных тестовых данных; реальные записи для проверки не использовались.
3. Разобрать существующие ошибки публичного typecheck в отдельном техническом проходе; текущая проверка подтверждает их в backend/admin, фикстурах, object storage и request API, но базовое состояние этой уже изменённой ветки отдельно не воспроизводилось.
