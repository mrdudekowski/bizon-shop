# Админка BIZON: полный фронтенд

Дата: 2026-09-25. Статус: утверждена. Дополняет `2026-09-25-frontend-cms-design.md`. Где документы расходятся, верен этот файл.

Публичные имена полей совпадают с `main-app` `src/lib/content/types.ts` и `src/lib/content/pages/types.ts`. Админка эти файлы не импортирует. Картинки и PDF в админке — не URL, а ссылка на файл библиотеки.

## Решения, закрывающие дыры

- Картинка в админке всегда `ImagePlacement`: `assetId`, `alt`, `focalX`, `focalY`, `crop` `{x,y,width,height}`. Числа фокуса и кадра от 0 до 1. При сохранении значения вне диапазона приводятся к ближайшей границе 0 или 1. Новых кодов ошибок для кадра нет.
- Галерея — упорядоченный массив `ImagePlacement`. PDF — массив `{ assetId, title }`. Оригинал файла не режется.
- Направление шины — документ с черновиком и снимком, как тип диска. Стартовое направление `dir-long-haul` / `long-haul` / «Магистральные» остаётся. Если в хранилище направление ещё плоский объект без `draft`, адаптер оборачивает его в документ при чтении.
- Страница — объединение по ключу, не одна плоская карточка. Если сохранённая страница не содержит `hero`, эта страница заменяется пустым стартовым документом того же ключа. `preferredWheelSlugs` в черновике нет.
- Текст статьи и истории — строка `body`. Дата публикации и таксономия в этой фазе не редактируются.
- Смена роли есть. Отключение себя по-прежнему `cannot_disable_self`. Снятие последней активной роли администратора (отключение или смена на редактора) — `last_admin`. Свою роль менять можно, пока остаётся другой активный администратор.
- Поиск и фильтр списка считаются по уже загруженному списку, без нового запроса.
- Пустые технические колонки размера, пустые преимущества и пустая галерея публикацию не блокируют.
- Повреждённый JSON хранилища: адаптер поднимает флаг, оболочка показывает «Хранилище повреждено, восстановлены стартовые данные» и пишет стартовый набор.
- Новых зависимостей нет. Стили — CSS modules, mobile-first, у сетки явные `grid-template-columns`, у ячеек `min-width: 0`, у ширины 100% есть `max-width: 100%`.

## Направление шины

Поля: `name`, `slug`, `description`, `shortDescription`, `sortOrder`, `showInMenu`, `mainImage?`, `selectionVehicleTypes`, `selectionConditions`. Осей нет.

Публикация: название, slug, главное фото. Те же блокеры, что у типа диска.

Экран: короткий список и документ. Создание спрашивает название.

## Модель шины

К уже существующей карточке, подбору и размерам добавляются:

- размер: `rimDiameter?`, `loadIndex?`, `loadIndexDual?`, `speedIndex?`, `plyRating?`, `overallDiameter?`, `sectionWidth?`, `treadDepth?`, `pressureSingleKpa?`, `pressureDualKpa?`, `maxLoadSingleKg?`, `maxLoadDualKg?`, `recommendedRim?`, `sku?`;
- `gallery`, `advantages` `{ id, title, description }`, `documents` `{ assetId, title }`;
- `showInMenu`, `menuOrder`.

Список: поле поиска по названию и фильтр «все / на сайте / скрыто».

Медиа: файл выбирается из библиотеки или загружается новым. У каждого места — подпись, фокус, кадр и превью (`object-position` из фокуса). Порядок галереи меняется кнопками «выше» и «ниже».

Низ документа показывает `lastSavedBy` и `lastPublishedBy`.

## Диски и shop

Тип диска и категория shop уже имеют название, slug, описание, фото, порядок и меню. Документ типа и категории редактируется, не только создаётся из списка.

Модель диска: серия, материал, конструкция, посадка, короткое и полное описание, главное фото, галерея, PDF, меню. Вариант: размер, PCD, вылет, центральное отверстие, цвет, цена или «по запросу», наличие. Пустой SKU у диска в этой фазе нет.

Товар: название, категория, оба описания, цена уровня товара, главное фото, галерея. Вариант: цвет, размер, SKU, своя цена или «по запросу», наличие, фото места.

Публикация модели диска и товара не меняется: имя, slug, родитель, главное фото, читаемый размер каждой строки, цена числом или «по запросу».

## Страницы

Общие поля каждой страницы: `seoTitle`, `seoDescription`.

Остальные страницы (`about`, `contact`, `warranty`, `branding`, `become-a-supplier`, `privacy-policy`, `shop-delivery-returns`): `hero` с `eyebrow`, `title`, `lead`, необязательным `image`.

`home`:

- `hero`: eyebrow, title, lead, image, `primaryCta` и `secondaryCta` `{ label, href }`, `metricLabel`, `metricText`;
- `selectionEntry`, `directions`, `expertise`: eyebrow, title, lead;
- `shopCampaign`: eyebrow, title, lead, image, `cta`;
- `resume`: eyebrow, title, lead, две кнопки.

`shop-home`:

- `hero`: eyebrow, title, lead, image, `cta`;
- `wheelsIntro`: eyebrow, title, lead, `kicker`;
- `orderSteps`: строки `{ id, title, description }`;
- `categoryCarousel`: строки `{ id, kicker, title, action, href, desktopImage?, mobileImage?, alt }`;
- `vehicles`: eyebrow, title, lead, `cta`, строки слайдов `{ id, title, image?, alt }`.

Пустая сохранённая страница публикуется. Удаления нет. Сброс очищает снимок.

## Материалы

Статья и история: название, slug, анонс, текст, необязательное главное фото, галерея, меню. История дополнительно: имя клиента и отрасль. Публикация по-прежнему требует название, slug и текст.

## Медиатека и пользователи

Места использования считают главное фото, галерею, фото варианта, картинки страниц и PDF.

Пользователи: создание, отключение, смена роли. Пароль в хранилище не пишется.

## Вне объёма

Вход по паролю, база, HTTP, правка `main-app`, заявки, видео, конструктор страниц, новые значения подбора, редиректы, история версий, перетаскивание кадра мышью.

## Рецензия

Проверено против дизайна от 2026-09-25 и публичных типов `main-app`.

Дыр, которые блокируют сборку, нет: форма страниц, направление как документ, миграция старого хранилища, кадр, смена роли и места использования файлов названы. Лишние публичные поля диска (диаметр, вес, крепёж, designStyle) в эту поставку не входят — их не было в согласованном документе диска.
