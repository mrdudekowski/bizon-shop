# Разделение корзин Bizon и BIZON Shop

**Статус:** концепция согласована пользователем 2026-10-08.

## Цель

Разделить корзину основного сайта Bizon и корзину BIZON Shop. Товары набираются независимо, оформление отправляет отдельные заявки. Поля обеих форм остаются одинаковыми.

## Текущая проблема

`SiteShell` использует общий `useCart` для основного сайта и маршрутов `/shop`. Общими являются счётчик, боковая корзина, клиентское состояние и серверная сессия. Страница `/cart` передаёт все позиции одним запросом с `sourceForm: "cart"`.

## Целевая модель

- Корзина Bizon содержит шины и позиции подбора шин.
- Корзина BIZON Shop содержит кованые диски и остальные товары Shop.
- Обе корзины используют единое ядро операций, но тип корзины обязателен при чтении, изменении, удалении, очистке и отправке.
- Шапка, меню и боковая корзина показывают счётчик и содержимое только текущей витрины.
- Страница `/cart` оформляет заявку Bizon; новая страница `/shop/cart` оформляет заявку BIZON Shop.
- Формы имеют одинаковые поля. Запросы различаются источником/типом заявки и составом позиций.
- Успешная отправка очищает только отправленную корзину. Ошибка отправки сохраняет её позиции и введённые данные для повтора.

## Хранение и перенос

Серверное API сохраняет корзины отдельно по типу, срок хранения остаётся 30 дней. Клиентское хранилище также использует отдельные ключи для Bizon и Shop. Одноразовый переход со старой общей корзины распределяет позиции по `itemType`: `tire` в Bizon, `wheel` и `shopProduct` в Shop. После подтверждённого переноса старая запись удаляется, чтобы не создавать дубли.

## Поведение интерфейса

- На основном сайте счётчик и drawer относятся к корзине Bizon; действия ведут на `/cart`.
- В `/shop` и вложенных маршрутах счётчик и drawer относятся к корзине Shop; действия ведут на `/shop/cart`.
- Каждая страница заказа показывает только свою группу позиций и при пустом состоянии предлагает перейти в каталог своей витрины.
- Изменение количества и удаление влияют только на активную корзину.

## Заявки и аналитика

Обе формы используют текущий API заявок и одинаковый набор полей. Для различения заявок передаются разные значения источника формы и только соответствующие позиции. События открытия, добавления и удаления корзины маркируются типом корзины.

## Проверки при реализации

1. Счётчики и drawer не показывают позиции другой витрины.
2. Добавление, изменение количества, удаление и очистка изолированы по типу.
3. Старые позиции переносятся в правильные корзины ровно один раз.
4. `/cart` и `/shop/cart` отправляют отдельные заявки с правильными позициями и типом источника.
5. Успешная отправка очищает только нужную корзину; ошибка сохраняет состояние для повтора.
6. Прямое открытие обеих страниц и пустые состояния работают корректно.

## Границы

В концепцию не входят разные наборы полей, отдельные API заявок, изменение бизнес-правил ценообразования или внедрение оплаты. Менеджер по-прежнему проверяет наличие, совместимость и стоимость.
