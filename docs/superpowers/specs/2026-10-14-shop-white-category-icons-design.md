# Белые иконки категорий Bizon Shop

## Цель

Показывать в раскрывающейся панели Bizon Shop белые пиктограммы с прозрачным фоном для всех видимых категорий. Для категории «Аксессуары» (ID `5`, slug `accessory`) использовать белую футболку. Каждая пиктограмма должна быть загруженным медиафайлом, выбранным для поля «Иконка» соответствующей плитки в CMS.

## Текущее устройство

- Раскрывающаяся панель использует `iconUrl` из `shopHomeCategoryCards`; при отсутствии иконки код подставляет изображение категории или фото-резерв.
- Страница `shop-home` хранит отдельные поля `icon`, `image` и `carouselImage` на каждую плитку.
- Backend сохраняет `icon` в `pages_shop_catalog_tiles.icon_media_id` и отдаёт URL назначенного медиа.
- CMS уже предоставляет поле «Иконка» через общий media placement. Загрузчик backend принимает PNG, JPEG и WebP, но не SVG.
- В текущем локальном опубликованном списке видны категории: «Кемпинг и путешествия» (ID `1`), «Аксессуары» (`5`), «Комфорт в автомобиле» (`2`), «Масла и запчасти» (`3`) и «Прицепы» (`4`). У плиток `shop-home` поля иконок сейчас пусты.

## Решение

1. Подготовить отдельные прозрачные PNG-пиктограммы в одном стиле для перечисленных категорий; иконка «Аксессуары» — белая футболка. Фотографии категорий, фото плиток и изображения карусели не переиспользовать и не заменять.
2. Создать/загрузить файлы через штатный backend media upload, чтобы они появились в медиа CMS как самостоятельные активы.
3. В редакторе «Shop → Плитки категорий» назначить соответствующий актив в поле «Иконка» каждой из пяти видимых плиток и сохранить страницу `shop-home`. Не менять видимость, сортировку, фото плиток или карусели.
4. Обеспечить различимое превью прозрачной белой иконки в CMS на контрастном нейтральном фоне. Сам фон остаётся только фоном превью; он не добавляется в файл.
5. В витрине выводить изображение, назначенное в поле иконки. Не применять фильтр, который может выбелить фотографии из резервных источников; неизвестная или отсутствующая иконка не должна подменяться фотографией в пиктограммной панели.

## Поток данных

```text
Прозрачный PNG → backend media upload → запись media → CMS media library
                                              ↓
                                  shop-home tile.icon.assetId
                                              ↓ save
                           pages_shop_catalog_tiles.icon_media_id
                                              ↓ publish snapshot
                       опубликованный iconUrl → иконка панели Shop
```

## Поведение и границы

- Активность в редакторе означает, что медиа назначено в поле «Иконка» плитки и сохранено; выбранный актив отображается с превью.
- Изменение публичной витрины требует обычной команды публикации `shop-home`. Публикация не запускается без отдельного подтверждения после локального сохранения и проверки результата.
- Не менять миграции, модель медиа, подписи категорий, существующие изображения/карусели и другие CMS-экраны.
- Если штатная загрузка локального backend не может сохранить актив из-за отсутствия объектного хранилища или доступа к CMS, не создавать обходную запись в БД; сообщить конкретный блокер и оставить готовые PNG и код.

## Проверка результата

- PNG имеют корректную сигнатуру, прозрачные пиксели вокруг белой пиктограммы и белый непрозрачный знак.
- В CMS после загрузки и сохранения повторное чтение `shop-home` возвращает пять соответствий `categoryId → icon.assetId`; media list возвращает каждому ID корректный image MIME type и URL.
- Превью белой футболки видно на фоне CMS, а другие четыре пиктограммы распознаваемы и визуально согласованы.
- Backend возвращает заполненные `iconUrl` для назначенных плиток; карточки витрины используют их и не подхватывают фото категории.
- До отдельного решения о публикации публичный snapshot остаётся прежним; после разрешённой публикации повторно проверяются revision/snapshot и `/shop`.
