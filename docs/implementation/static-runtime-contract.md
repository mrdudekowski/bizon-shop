# Контракт статического сайта, CMS и backend

Зафиксировано 7 октября 2026 года во время перехода на статическую публикацию. Runtime-поведение опубликованного CMS-контента уточнено 24 октября 2026 года: страницы остаются статическими для SEO, а браузер при загрузке перечитывает опубликованные данные из backend API. Локальная PostgreSQL остаётся рабочей базой. Timeweb Apps, домены и облачная БД этим изменением не создаются.

## Публичный сайт

HTML, метаданные, изображения страниц и `sitemap.xml` создаются во время сборки из опубликованных данных, которые backend отдаёт через `CONTENT_API_URL`. Сборка в production завершается ошибкой, если API не задан или данные не загрузились. Черновики в публичный экспорт не попадают.

| Действие | Адрес backend | Кто выполняет |
|---|---|---|
| Прочитать опубликованные шины, модели и размеры | `GET /v1/tires/...` | сборка сайта |
| Прочитать опубликованные диски и модели | `GET /v1/wheels/...` | сборка сайта |
| Прочитать товары и категории магазина | `GET /v1/shop/...` | сборка сайта |
| Прочитать страницы и Tire IQ | `GET /v1/pages/...`, `GET /v1/articles...` | сборка сайта |
| Обновить главную Shop после загрузки | `GET /v1/pages/shop-home`, `GET /v1/shop/categories`, `GET /v1/wheels/types/forged/models` | браузер → backend |
| Обновить категорию и опубликованные товары | `GET /v1/shop/categories/{slug}`, `GET /v1/shop/products?category={slug}` | браузер → backend |
| Обновить карточку товара, цену и варианты | `GET /v1/shop/products/{slug}` | браузер → backend |
| Обновить модель диска и варианты | `GET /v1/wheels/types/{slug}`, `/v1/wheels/models/{type}/{slug}`, `/v1/wheels/models/{id}/variants` | браузер → backend |
| Обновить варианты модели шины и их цены | `GET /v1/tires/models/{id}/variants` | браузер → backend |
| Обновить главную, включая все CMS-секции и карточки шин | `GET /v1/pages/home`, `GET /v1/tires/types`, `GET /v1/tires/types/{slug}/models` | браузер → backend |
| Обновить фиксированные CMS-страницы | `GET /v1/pages/{key}` | браузер → backend; About, Contact, Warranty, Branding, Supplier, Privacy и Shop Delivery/Returns |
| Обновить каталог и страницу направления шин | `GET /v1/tires/types`, `/v1/tires/types/{slug}`, `/v1/tires/types/{slug}/models` | браузер → backend |
| Обновить модель шины и варианты | `GET /v1/tires/models/{type}/{slug}`, `/v1/tires/models/{id}/variants` | браузер → backend |
| Обновить каталог и страницу типа дисков | `GET /v1/wheels/types/{slug}`, `/v1/wheels/types/{slug}/models`, `/v1/wheels/types/{slug}/variants` | браузер → backend |
| Обновить список и статью Tire IQ | `GET /v1/articles`, `GET /v1/articles/{slug}` | браузер → backend |
| Обновить записи меню | опубликованные tire/wheel модели, статьи и категории Shop через соответствующие GET-маршруты | браузер → backend при первом открытии меню |
| Отправить заявку | `POST /v1/requests` | браузер → backend; проверка, нормализация, защита от спама и запись в БД выполняются backend |
| Прочитать, сохранить или очистить корзину | `GET/PUT/DELETE /v1/cart` | браузер → backend; идентификатор сессии — HttpOnly cookie backend |

Фильтры шин и Tire IQ, а также тема контактной формы читаются браузером из адреса страницы. Они не требуют серверного рендера.

## CMS

CMS экспортируется в обычные статические файлы. Сборка завершается ошибкой, если `NEXT_PUBLIC_ADMIN_API_URL` не задан. CMS обращается к этому адресу напрямую; в переменной может быть только публичный адрес backend. Серверные cookie, проверка ролей, чтение и запись БД, загрузка файлов и работа с S3 остаются в backend.

| Действие | Адрес backend | Кто выполняет |
|---|---|---|
| Войти, проверить сессию, выйти | `/v1/admin/auth/login`, `/session`, `/logout` | браузер CMS → backend; cookie HttpOnly |
| Читать и менять CMS данные | `POST /v1/admin` | браузер CMS → backend; роли и права проверяются backend |
| Загрузить или заменить файл | `POST /v1/admin/assets`, `PUT /v1/admin/assets/{id}` | браузер CMS → backend → S3 и БД |
| Отменить замену файла | `DELETE /v1/admin/assets/{id}/replacement` | браузер CMS → backend |
| Удалить файл | операция admin API | backend; запрещает удаление используемого файла и пишет историю |
| Сбросить пароль | операция admin API | второй администратор через backend |
| Опубликовать изменение | `publish...` или `publishChangeSet` через admin API | backend; обновляет опубликованный снимок |

ID редактора CMS передаётся в строке запроса (`/materials/editor?id=...`), поэтому список возможных ID не нужно заранее встраивать в статическую сборку.

## Обновление публичных страниц после публикации

SEO HTML, метаданные, sitemap и начальные данные остаются снимком на момент сборки. После публикации браузер перечитывает актуальные тексты и URL изображений для существующих страниц: главной, фиксированных CMS-страниц, Tire IQ, типов и моделей шин, типов и моделей дисков, Shop home, категорий и товаров. CMS-пункты меню обновляются при первом открытии меню. Запросы выполняются без браузерного кэша и без периодического опроса. Поэтому новая публикация видна при следующем открытии или перезагрузке страницы. При недоступности API остаётся сгенерированная версия.

`NEXT_PUBLIC_API_URL` должен быть задан при сборке frontend и указывать на публичный backend. `CORS_ALLOWED_ORIGINS` backend должен разрешать точный origin сайта. Изменения SEO, sitemap и метаданных, а также появление новых или переименованных URL требуют пересборки и деплоя. Новая запись с ранее неизвестным slug не получит статический файл до этой пересборки. Публикация в CMS сама по себе не подтверждает, что production API, CORS и deployed frontend настроены правильно.

После успешной публикации backend по-прежнему может запускать сборку приложения `main-app`: она обновляет SEO HTML, sitemap и список статических URL. Это не является способом обновить runtime-данные `/shop`. Сохранение черновика не запускает сборку. Токен и ID публичного приложения принадлежат только backend. Если запуск не удался, CMS сообщает об этом и администратор может повторить попытку.

Путь запуска деплоя подтверждён в официальном SDK Timeweb: `POST /api/v1/apps/{app_id}/deploy` ([официальный SDK](https://github.com/timeweb-cloud/sdk-go/blob/main/api_apps.go)). Тело запроса в SDK не передаётся. Права токена, ID приложения и фактический ответ API ещё нужно сверить в аккаунте.

## Ограничения до выбора доменов

При локальной работе сайт и CMS используют backend на том же компьютере; backend разрешает только заданные origin. Для браузерного чтения опубликованных данных production-переменная `CORS_ALLOWED_ORIGINS` backend должна включать точный публичный origin сайта. В Timeweb технические адреса сайта, CMS и API могут оказаться на разных доменах. `SameSite=Lax` не переносит CMS-сессию между разными сайтами. До финального включения CMS должны получить адреса на одном родительском домене или иной проверенный same-site план. Домены ещё не выбраны, поэтому вход CMS на технических адресах не считается финальной проверкой.

Статическая сборка Next.js прошла локально и создала `out/` с HTML-файлами для опубликованных динамических URL, `robots.txt` и `sitemap.xml`. Настройка прямой выдачи этих файлов и SPA fallback в Timeweb пока не проверена: для этого нужно техническое приложение и ручная проверка прямого открытия и обновления страницы. Пока fallback не доказан, после публикации требуется собирать каждый известный URL как отдельный HTML-файл.
