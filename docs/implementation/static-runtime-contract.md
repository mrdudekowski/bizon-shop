# Контракт статического сайта, CMS и backend

Зафиксировано 7 октября 2026 года во время перехода на статическую публикацию. Локальная PostgreSQL остаётся рабочей базой. Timeweb Apps, домены и облачная БД этим изменением не создаются.

## Публичный сайт

HTML, метаданные, изображения страниц и `sitemap.xml` создаются во время сборки из опубликованных данных, которые backend отдаёт через `CONTENT_API_URL`. Сборка в production завершается ошибкой, если API не задан или данные не загрузились. Черновики в публичный экспорт не попадают.

| Действие | Адрес backend | Кто выполняет |
|---|---|---|
| Прочитать опубликованные шины, модели и размеры | `GET /v1/tires/...` | сборка сайта |
| Прочитать опубликованные диски и модели | `GET /v1/wheels/...` | сборка сайта |
| Прочитать товары и категории магазина | `GET /v1/shop/...` | сборка сайта |
| Прочитать страницы и Tire IQ | `GET /v1/pages/...`, `GET /v1/articles...` | сборка сайта |
| Отправить заявку | `POST /v1/requests` | браузер → backend; проверка, нормализация, защита от спама и запись в БД выполняются backend |
| Прочитать, сохранить или очистить корзину | `GET/PUT/DELETE /v1/cart` | браузер → backend; идентификатор сессии — HttpOnly cookie backend |

Фильтры шин и Tire IQ, а также тема контактной формы читаются браузером из адреса страницы. Они не требуют серверного рендера.

## CMS

CMS экспортируется в обычные статические файлы. Сборка завершается ошибкой, если `NEXT_PUBLIC_ADMIN_API_URL` не задан. CMS обращается к этому адресу напрямую; в переменной может быть только публичный адрес backend. Серверные cookie, проверка ролей, чтение и запись БД, загрузка файлов и работа с S3 остаются в backend.

| Действие | Адрес backend | Кто выполняет |
|---|---|---|
| Войти, проверить сессию, выйти | `/v1/admin/auth/login`, `/session`, `/logout` | браузер CMS → backend; cookie HttpOnly |
| Читать и менять CMS данные | `POST /v1/admin` | браузер CMS → backend; роли и права проверяются backend |
| Загрузить или заменить файл | `POST /v1/admin/assets`, `PUT /v1/admin/assets/{id}` | браузер CMS → backend → S3 и БД |
| Отменить замену файла | `DELETE /v1/admin/assets/{id}/replacement` | браузер CMS → backend |
| Удалить файл | операция admin API | backend; запрещает удаление используемого файла и пишет историю |
| Сбросить пароль | операция admin API | второй администратор через backend |
| Опубликовать изменение | `publish...` или `publishChangeSet` через admin API | backend; обновляет опубликованный снимок |

ID редактора CMS передаётся в строке запроса (`/materials/editor?id=...`), поэтому список возможных ID не нужно заранее встраивать в статическую сборку.

## Обновление публичных страниц после публикации

Публичные страницы остаются снимком на момент сборки. После успешной публикации backend запускает новую сборку приложения `main-app` через Timeweb API. Сохранение черновика не запускает сборку. Токен и ID публичного приложения принадлежат только backend. Если запуск не удался, CMS сообщает об этом и администратор может повторить попытку.

Путь запуска деплоя подтверждён в официальном SDK Timeweb: `POST /api/v1/apps/{app_id}/deploy` ([официальный SDK](https://github.com/timeweb-cloud/sdk-go/blob/main/api_apps.go)). Тело запроса в SDK не передаётся. Права токена, ID приложения и фактический ответ API ещё нужно сверить в аккаунте.

## Ограничения до выбора доменов

При локальной работе сайт и CMS используют backend на том же компьютере; backend разрешает только заданные origin. В Timeweb технические адреса сайта, CMS и API могут оказаться на разных доменах. `SameSite=Lax` не переносит CMS-сессию между разными сайтами. До финального включения CMS должны получить адреса на одном родительском домене или иной проверенный same-site план. Домены ещё не выбраны, поэтому вход CMS на технических адресах не считается финальной проверкой.

Статическая сборка Next.js прошла локально и создала `out/` с HTML-файлами для опубликованных динамических URL, `robots.txt` и `sitemap.xml`. Настройка прямой выдачи этих файлов и SPA fallback в Timeweb пока не проверена: для этого нужно техническое приложение и ручная проверка прямого открытия и обновления страницы. Пока fallback не доказан, после публикации требуется собирать каждый известный URL как отдельный HTML-файл.
